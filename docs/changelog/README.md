# Changelog

What changed, when, and what it means. Not a commit log — git already holds that. This records changes to the *system*: new frameworks, changed positions, structural decisions, retired ideas.

## Format

One file per month, named `YYYY-MM.md`, newest linked first. Within a file, entries run newest-first under four headings:

- **Method** — frameworks and principles added, revised or retired
- **Content** — narratives and articles published
- **System** — structural, schema or infrastructure changes
- **Retired** — positions or artefacts withdrawn, and why

## What belongs here

An entry earns a place if someone returning after a month would be wrong without it. A published article qualifies. A typo fix does not. A changed position always qualifies — and should say what changed the mind, since a position whose reasoning is not recorded cannot be revisited when the evidence moves again.
