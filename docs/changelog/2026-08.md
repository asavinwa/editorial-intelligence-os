# 2026-08

## System

**Repository licensed, and CI added.** A dual licence — CC BY 4.0 for documentation, frameworks and content; MIT for site code — replaces the implicit all-rights-reserved default that applied while the public repository carried no `LICENSE`. A methodology arguing for portable, reusable knowledge needed usage terms that permit exactly that.

A GitHub Actions workflow now builds the site on every push and pull request. This is partly a signal that the repository is engineered rather than assembled, and partly practical: the content schemas already fail the build on an out-of-vocabulary tag or malformed frontmatter, so CI catches those before they reach the site.

`.claude/settings.local.json` was removed from tracking — it carried local machine paths and internal document filenames into a public repository — and is now ignored.

**Public repository evolution proposed, then scoped down.** A full proposal for turning the repository into the canonical public home of the methodology was written and then largely parked. The original assumption was that visitors would explore the repository and read their way into the discipline; the audience — marketing, communications and product practitioners — does not browse repositories. The revised objective is that the repository should demonstrate at a glance that this is a real, maintained system, without requiring anyone to dig into it. Phase 1 shipped; the remainder is held in reserve with the conditions that would un-park it. See [public repository evolution](../roadmap/public-repository-evolution.md).

**Repository restructured into three layers.** The Astro site moved from the repository root into `website/`, and two new top-level directories were added: `docs/` for the method (philosophy, principles, framework index, roadmap, changelog) and `research/` for public notes and experiment logs. Vercel now builds via a root `vercel.json` pointing at `website/`.

The reasoning: the published site and the method behind it were the same directory tree, which made it impossible to document the system without publishing the documentation. Separating them means the method can be developed at its own pace.

**Four principles documented.** Compounding, structure before volume, judgement as the scarce input, and system over individual — extracted from positions already argued in the published writing and stated as constraints in `docs/principles/`.
