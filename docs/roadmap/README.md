# Roadmap

What is being built next, and why. Direction rather than dates — the system is developed alongside client work, so sequence is committed and timing is not.

## How this is organised

| Horizon | Meaning |
| --- | --- |
| **Now** | In progress, with work visible in the repository |
| **Next** | Committed, not started |
| **Later** | Directionally agreed, not specified |
| **Not doing** | Considered and declined, with the reason |

The last section matters as much as the others. A roadmap that only records what was chosen loses the reasoning that ruled things out, and the same proposals return every quarter.

## Current state

- [Now, next and later](current.md) — the live position
- [Open questions](open-questions.md) — decisions that shape the roadmap but are not yet made

## Maintaining this

Review when something moves horizon, not on a schedule. When an item ships, move it to the [changelog](../changelog/) with a note on what it changed — the roadmap records intent, the changelog records what actually happened, and the gap between them is the most useful signal either one produces.
