# Principles

Frameworks tell you how to do a particular thing. Principles tell you what to do when no framework fits.

These are the working rules that govern decisions across the system. Each is extracted from positions already argued in the published content — the source is linked at the foot of each page. They are stated as constraints rather than aspirations, because a principle that cannot rule anything out is not doing any work.

| Principle | The rule |
| --- | --- |
| [Knowledge must compound](compounding.md) | If a piece of work makes the next one no cheaper or better, the system has not done its job |
| [Structure before volume](structure-before-volume.md) | Unstructured knowledge cannot be found, reused, or handed to an agent |
| [Judgement is the scarce input](judgement-is-scarce.md) | Automate production; never automate the decision about what is worth saying |
| [The system outlives the individual](system-over-individual.md) | Knowledge held only in someone's head is a liability, not an asset |

## Using these

When a decision is genuinely open — a new format, a new tool, a request that does not fit the existing shape — work down the list in order. Compounding is the first test because it is the one the whole method exists to satisfy. If a proposal fails it, nothing further down rescues it.

## Adding a principle

A principle earns a place here when it has (a) ruled out a real decision at least twice, and (b) a published argument behind it. Add the file, link it from the table above, and cite the source. Restating a framework is not a principle.
